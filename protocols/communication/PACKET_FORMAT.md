
# SPEC-P6 Data Packet Format

## Overview

SPEC-P6 Sensor Nodes transmit measurement data to the Coordinator using a structured binary data packet over ESP-NOW.

The packet format is defined in:

`/firmware/common/common_definitions.h`

Each data packet contains up to five consecutive measurement samples.

## Data packet structure

The measurement packet is defined as:

```cpp
typedef struct __attribute__((packed)) struct_data_packet {
    uint8_t sample_count;
    uint16_t battery_mv;
    struct_single_sample samples[SAMPLES_PER_PACKET];
} struct_data_packet;
```
The current firmware defines:

```cpp
#define SAMPLES_PER_PACKET 5
```
Therefore, a complete packet can contain five measurement samples.

Packet fields
| Field          | Data type                 | Description                                     |
| -------------- | ------------------------- | ----------------------------------------------- |
| `sample_count` | `uint8_t`                 | Number of valid samples contained in the packet |
| `battery_mv`   | `uint16_t`                | Battery voltage in millivolts                   |
| `samples`      | `struct_single_sample[5]` | Array containing up to five measurement samples |

Measurement sample structure

Each measurement sample is defined as:

```cpp
typedef struct __attribute__((packed)) struct_single_sample {
    uint64_t timestamp_us;
    uint32_t red;
    uint32_t ir;
    int16_t ax;
    int16_t ay;
    int16_t az;
    int16_t gx;
    int16_t gy;
    int16_t gz;
    float instantaneousFs;
} struct_single_sample;
```
Each sample therefore contains the following fields:

| Field             | Data type  | Description                               |
| ----------------- | ---------- | ----------------------------------------- |
| `timestamp_us`    | `uint64_t` | Sensor Node timestamp in microseconds     |
| `red`             | `uint32_t` | MAX30102 red-channel measurement          |
| `ir`              | `uint32_t` | MAX30102 infrared-channel measurement     |
| `ax`              | `int16_t`  | Accelerometer X-axis measurement          |
| `ay`              | `int16_t`  | Accelerometer Y-axis measurement          |
| `az`              | `int16_t`  | Accelerometer Z-axis measurement          |
| `gx`              | `int16_t`  | Gyroscope X-axis measurement              |
| `gy`              | `int16_t`  | Gyroscope Y-axis measurement              |
| `gz`              | `int16_t`  | Gyroscope Z-axis measurement              |
| `instantaneousFs` | `float`    | Instantaneous sampling-frequency estimate |
Timestamp

Each measurement sample contains its own timestamp:

timestamp_us

The timestamp is expressed in microseconds and is generated by the Sensor Node.

The timestamp is associated with the individual measurement sample rather than with the ESP-NOW packet as a whole.

Sampling and packetization

The target acquisition frequency is 50 Hz.

The firmware groups five consecutive samples into a single ESP-NOW data packet:

50 samples/s
       ↓
5 samples/packet
       ↓
10 packets/s per Sensor Node

With three Sensor Nodes operating simultaneously:

3 nodes × 10 packets/s = 30 packets/s

This represents the nominal application-level packet generation rate.

Battery information

Battery voltage is included once per data packet through:

battery_mv

The value is expressed in millivolts.

Data flow

The measurement data follow this path:

MAX30102 ─┐
          │
          ├── Sensor Node
MPU6050 ──┘
              │
              │ struct_data_packet
              ▼
          ESP-NOW
              │
              ▼
         Coordinator
              │
              │ Serial
              ▼
        Host computer
Control packet

Control commands from the Coordinator to the Sensor Nodes use a separate structure:

typedef struct __attribute__((packed)) struct_cmd_packet {
    char command;
} struct_cmd_packet;

The command packet contains a single character representing the requested operation.

Status packet

The firmware also defines a status packet:

typedef struct __attribute__((packed)) struct_status_packet {
    char message[16];
} struct_status_packet;

This structure is used for short status messages exchanged by the system.

Memory layout

All communication structures are declared using:

__attribute__((packed))

This prevents compiler-introduced padding between structure members and provides a defined compact memory layout for transmission.

Source definition

The complete packet definitions are maintained in:

/firmware/common/common_definitions.h

Any modification to the communication structures should be reflected in this document.
